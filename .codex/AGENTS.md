# AGENTS.md

本文件是 `/home/hsw/catkin_ws/program` 项目的 AI 编程规则。后续 Agent 在本项目内执行代码阅读、修改、测试和交付时，必须遵守以下要求。

## 1. 提示词规范化流程

收到用户任务后，不要立即修改代码。先对用户提示词进行规范化重构：

1. 识别核心意图。
2. 提取任务目标、输入信息、输出要求、风格要求、约束条件和缺失参数。
3. 将原始提示词整理为更清晰、结构化、可执行的 prompt。
4. 如果存在不确定、缺失、冲突或会影响结果质量的参数，先按要点反问用户。
5. 用户补充后，再整合为最终可执行 prompt。
6. 如果信息已经足够，直接给出规范化后的 prompt，并开始执行任务。

## 2. 修改前必须阅读上下文

修改代码前必须先阅读相关源码、配置和文档，避免凭印象修改。

涉及以下程序时，必须先阅读根目录的 `AI_CODE_INDEX.md`：

- `FastLioBodyBev_ros1`
- `GridMap_v7_5_ros1`
- `dem_loc`

需要重点确认：

- 当前入口文件、核心类和数据流。
- ROS 话题名、消息类型、frame、参数名。
- 配置文件和运行脚本。
- 已有用户改动和未提交文件。

## 3. 最小改动原则

只做完成当前任务必需的最小修改。

禁止行为：

- 顺手重构无关代码。
- 格式化未参与任务的文件。
- 修改与任务无关的命名、目录、配置或注释。
- 为了个人偏好替换已有实现风格。
- 在没有明确收益和任务要求时新增抽象层。

如果发现可改进但不属于本次任务的问题，只在最终回复中说明，不直接修改。

## 4. 接口兼容原则

除非用户明确要求，否则不得改变既有接口和外部契约。

默认禁止修改：

- ROS 话题名。
- ROS 消息类型和字段语义。
- frame 名称和坐标系约定。
- 参数名、配置 key 和默认路径。
- `grid_map_msgs/GridMap` 图层名。
- 脚本入口、可执行文件名和运行方式。
- Python 包名、模块路径和公开函数签名。
- C++ 类的公开接口和已有调用方式。

特别注意 `/lidar_bev/grid_map` 的跨包契约，默认必须保留以下图层名和语义：

- `H_rel_surf`
- `M_L`
- `G_long_L`
- `G_lat_L`

如果任务确实需要改变接口，必须先说明影响范围、调用方、迁移方式和测试计划。

## 5. 严格遵守计划边界

只修改已确认 plan 中包含的程序、模块和文件。

不得修改：

- plan 之外的程序。
- plan 之外的配置。
- plan 之外的历史逻辑。
- build、bin、cache、`__pycache__` 等生成产物。

如果实施过程中发现 plan 不完整，必须暂停并说明需要调整的点，不得自行扩大范围。

## 6. 保护用户已有改动

工作区可能已有用户改动。Agent 必须保护这些改动。

必须做到：

- 修改前查看 `git status --short`。
- 不覆盖、不回滚、不格式化用户已有改动。
- 如果必须编辑已有改动所在文件，先理解现有改动并在其基础上最小修改。
- 不使用 `git reset --hard`、`git checkout --`、`git clean` 等破坏性命令，除非用户明确要求。
- 不删除未知文件和未跟踪文件。

## 7. 完成后的自我 Review

每次完成代码或文档修改后，必须进行自我 review。

review 至少包括：

- 检查 diff 或新增文件内容。
- 确认只修改了计划内文件。
- 确认没有引入计划外重构。
- 确认没有改变既有接口和跨包契约。
- 确认没有覆盖用户已有改动。
- 检查命名、路径、注释和文档是否与项目现状一致。

如果发现问题，必须先修正，再进入测试或验证。

## 8. 完成后的测试和验证

每次修改后必须做测试或验证。测试强度根据修改风险确定。

优先选择：

- 直接运行相关单元测试或脚本测试。
- 对 ROS 程序进行构建检查。
- 对 Python 文件运行语法检查。
- 对配置或文档修改进行关键词、路径和内容校验。
- 对跨包接口修改进行生产者和消费者两侧检查。

如果无法运行测试，必须在最终回复中说明：

- 为什么无法运行。
- 已完成哪些替代验证。
- 剩余风险是什么。

不得用“未测试”一句话代替说明。

## 9. 最终回复要求

任务完成后的最终回复必须包含：

- 修改摘要。
- review 结论。
- 测试或验证结果。
- 未完成项或剩余风险。

如果没有未完成项或剩余风险，明确说明。

## 10. 项目特定注意事项

本项目重点程序之间存在共享数据契约：

- `FastLioBodyBev_ros1` 和 `GridMap_v7_5_ros1` 都可能发布 `/lidar_bev/grid_map`。
- `dem_loc` 消费 `/lidar_bev/grid_map` 并解析固定图层。
- 改 BEV 图层、分辨率、地图尺寸、梯度方向或坐标系时，必须同时检查生产端和 `dem_loc` 消费端。

优先阅读：

- `AI_CODE_INDEX.md`
- `FastLioBodyBev_ros1/config/body_bev.yaml`
- `GridMap_v7_5_ros1/config/GridMapInit.ini`
- `dem_loc/loc_tool/cinterface.py`
- `dem_loc/scripts/localization_python.py`
